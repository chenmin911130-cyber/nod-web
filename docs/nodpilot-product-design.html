NODPILOT · PRODUCT DESIGN

Nodpilot 产品功能设计

AI Listening Assistant
2026-09-04 · 公测

当场听懂正在发生的对话，结束后带走结构化笔记，之后还能搜回。

一条原则 场景只决定笔记长什么样，不另开一套产品。用户面对的永远是同一场听写：开始听 → 当场理解 → 决定留不留。
Listen当场听见：实时转写
Understand当场听懂：翻译 / Ask / 笔记
Remember事后记住：History 30 天

1. 用户要完成的事

不是「再做一个 GPT 聊天框」，也不是隐身面试小抄。目标用户是人在听：开会、上课、跨语言对话、现场问答。产品替他们把声音变成可以扫读、可以追问、可以带走的东西。

时刻用户在做什么产品给什么
开始前选场景、语言、麦克风Meeting / Lecture / Live Q&A / Translate；同意录音
进行中听别人说话，偶尔没跟上Live 转写、最新一句翻译、Ask
暂停 / 结束决定这场留不留Save = 提交进 History；Don't save = 丢掉 draft
之后复盘、交作业、给同事看打开 History、搜正文、导出 PDF / Files
做

浏览器 / iPhone / Watch 上的听写工作台。会议决策与待办、讲座概念与复习、跨语言字幕、现场问答草稿。账号同步 History。

不做

隐身截屏、系统扬声器抓 Zoom/Teams、跨会话记忆问答、Presentation 独立场景、桌面 Nod Agent。网页听不到耳机里对方的声音。

2. 信息架构

顶栏只有两个入口：Listen 和 Translate。Listen 里再用场景芯片选笔记模板。代码里仍是三个 workspace（meeting / interview / translate），Lecture 是 meeting 的 scene，不要再暴露给用户。

主路径

Listen

一场录音。场景决定 Notes 板块：Meeting 写决策与待办，Lecture 写概念与复习，Live Q&A 写问答与 takeaways。Ask、Save、History 都挂在这场上。

对照层

Translate

听一句出一句对照字幕。From 可 Auto，To 锁定目标语。Bilingual / More accurate 是显示开关，不是第二种产品。不进 Meeting 那套 Save 弹窗。

3. 场景 × 笔记

场景何时选进行中结束后的笔记Save
Meeting 多人讨论、要决策 转写 + 说话人 + 最新一句译文 Summary · Key Points · Decisions · Action Items · Important Details · Follow-ups Stop / Pause 后提交 History
Lecture 一个人讲、要复习 同一套听写，说话人可合并为讲师 Overview · Concepts · Examples · Revise · Homework 与 Meeting 相同
Live Q&A 听见问题，要口头回答 完整问题才起草答案；侧栏问答 Summary · Q&A Takeaways 不弹 Save；问答留在当场
Translate 当场要对着看字幕 原文 | 译文；可 TTS；Same lang 直通 对照 PDF，不是会议纪要 不弹 Save

语言是两层，不要合成一个开关

Speech 是听见什么语言（Auto 或钉死中/英/日）。Notes 是笔记用什么语言写。Translate 另有 From / To。听写中途不可切场景。

Meeting / Lecture 里的 Bilingual 开关同时控制逐句译文和 Notes 双语；它就是 translateOn，不是第三个开关。

Presentation 怎么处理

落地页写了 Presentation，产品里没有第四个 scene。先把它映射成 Lecture：一个人讲、听众要带走结构。等真实用量证明「演示」和「上课」笔记真的不同，再拆。

5. 对外承诺 vs 现在真正有的

承诺现状设计结论
可搜索记忆，之后还能问 History 关键词搜本场正文；保留 30 天；不能问「上周定价怎么定的」 对外改成「搜回这 30 天的场次」。跨会话 Ask 单独立项，未做就不写
Presentation 场景 只有 Meeting / Lecture / Live Q&A 文案映射到 Lecture，不新增 scene
语音提问、不用打字 Ask 主要是打字；Live Q&A 是听问题再起草 主路径保持打字 Ask。语音问要单独做，不要和听写抢同一只麦
隐私：当场不留原始音频 Save 勾 Keep recording 会把 WAV 存 R2 法律页与弹窗必须说清：默认可留录音，用户可关掉
产品说明书：面试隐身小抄 品牌已是 Listening Assistant；Live Q&A 仍带 STAR 口头答案 说明书跟产品走。Live Q&A 是现场起草，不是对面试官隐身

6. 动词已经定过，不要再混

Save

把当前 draft 标成 kept，进账号 History。不结束会话，不导出到 Files。

Don't save

丢掉这份 draft。没进 History，之后导不出来。

Save to Files

只对已经 kept 的会话。拷 PDF / 录音到 iPhone Files 或电脑下载。

Summarize

对当前 transcript 一次性生成 Notes，可在听的过程中按；Stop 后自动按一次。

Notes

结构化笔记，桌面 / iPhone / PDF / History 同一份、同一套标题。

两轴状态（ADR 0001）

capture 是麦还在不在听（off / listening / recording / paused）。engine 是模型在不在干活（idle / transcribing / generating）。生成中不得被看成 Stop。Watch 和手机都读 capture，不要再用 run=think 推断听写。

7. 路线

公测期功能设计的工作是把现在已经有的能力说圆、用稳，而不是再开第四个工作区。按「不做会伤品牌」排序。

优先级做什么为什么现在做明确不做
P0 Listen / Translate / Watch / Save 主路径保持正确 这就是产品。麦、场景、busy、Save 任一错，用户会觉得「不能听」 不要同一轮改界面、同步、录音三层
P0 对外文案对齐真实能力 落地页 Memory / Presentation / 语音问 超出现状；说明书还在写面试小抄 不要为了文案去补一个假 Memory
P1 Remember 做诚实：30 天、能搜、能导出、能删 Remember 是三角的第三边；现在只有场内搜索 跨所有历史的 LLM 问答放到 P2
P1 Live Q&A 定位成现场起草，不是隐身 品牌已经离开「面试外挂」；能力可以留，话术要改 网页版不做 Stealth
P2 跨会话 Ask；桌面系统声（若重新开 Windows） 有真实用量再做。桌面是另一条线 废弃的 Nod Agent / 3080 不要碰

8. 建议立刻拍板的四件事

  1. 1. 对外只讲两个入口：Listen 和 Translate。 Meeting / Lecture / Live Q&A 是 Listen 的场景芯片，不是三个 App。
  2. 2. Memory 改口：搜回最近 30 天的场次。 跨周问答等真做了再写。History 打开时删掉超期会话，这条已经在产品里。
  3. 3. Save 继续只表示进 History。 Files / PDF 留在 History。Pause 后 Save 仍写同一条，不拆场。
  4. 4. 手表是这场听写的遥控器，不是第二个 Nodpilot。 模式跟随手机；只有当场 Listen 才切场景和麦。
